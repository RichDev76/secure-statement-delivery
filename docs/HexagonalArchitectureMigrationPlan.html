1Goal & guiding principles

Restructure statement-service so the package tree names business capabilities (statements, upload, download, search, signed links, audit) instead of technical layers (controller, service, util), and so the domain depends only on ports it owns, with framework and IO code pushed to adapters at the edge. The rules come from the house architecture standard (docs/standards/architecture.md):

  • Feature-first (Screaming Architecture): top-level packages are business capabilities. New code goes in the feature it serves; no util/common dumping grounds.
  • Hexagonal (Ports & Adapters): domain code depends on interfaces it owns; adapters implement them at the edge. The tell-tale violation: a domain service importing java.io.File, crypto classes, or a concrete infrastructure.* class. Spring Data repositories are tolerated as de-facto ports.
  • Controllers live inside their feature, in an infrastructure sub-package — HTTP is an adapter to the feature, not a layer above the app.
  • shared/ depends on nothing — not on features, not on infrastructure. No dependency cycles between features; features talk via public services only.
  • Contract-first is untouched: the OpenAPI yaml remains the source of truth; generated AdminApi/StatementsApi/AuditApi interfaces remain the inbound contracts.
  • Executable architecture: ArchUnit rules fail the build on violations; legacy violations are frozen (FreezingArchRule) and burned down phase by phase — rules are never weakened.

Dependency tangles to unwind

  • Audit is called from every feature via two inconsistent paths — AuditService directly (upload, download) and via util/AuditHelper (search).
  • Statements ↔ signed links coupling: StatementQueryService mints links via SignedLinkService; DownloadService validates/consumes them — and also bypasses the statements service to query StatementRepository directly.
  • util/ is load-bearing domain code: validation, audit recording, HTTP response building, HMAC signing, request-context reads.

Key structural decisions

#DecisionRationale
D1signedlink is a sub-capability of statement, sibling of upload/search/download — not a top-level feature, not part of downloadMeaningless without statements; both search (mint) and download (validate/consume) use it. Under download it would force a search → download edge; as a sibling the graph stays acyclic.
D2No OpenAPI restructuring. Tags Admin/Statements/Audit stay; generated packages stayTags already generate exactly the three mandated interfaces. StatementsApi spans search+get+download, so the single StatementsController sits at the feature root statement/infrastructure/, fronting two sub-capabilities.
D3Generated api/model.api classes become adapter-only by ArchUnit rule, not by relocationHouse standard fixes the generator packages. Rule: referenced solely from ..infrastructure.. — initially violated by F3, burned down via the freeze store.
D4ArchUnit lands first (Phase 1), frozen; the freeze store is deleted at the endFreeze-first turns migration into a ratchet: every phase must shrink the store, and new violations fail immediately. ArchUnit-last would leave the whole migration unprotected.
D5LoggingAspect is re-targeted before any move, to annotation pointcuts (@within(RestController) / @within(Service))Annotation pointcuts are package-move-invariant. Coverage is equivalent: every advised class today is @RestController/@Service.
D6Config-prefix bug (F2) fixed as an isolated pre-step PR, never buried in a move commitIt is behavior-affecting: after the fix, enabled/retention-period/batch-size/lock durations bind for the first time — their yml values (including infra/config-repo) must be reviewed in the same PR. Fix direction: singular, matching every yml.
D7DownloadService's repository bypass is fixed in-flight (Phase 6); splitting uploadStatement out of StatementService core is backlogDownloadService is already being reworked onto ports in that phase; the upload split is orthogonal and would inflate scope.

Deliberate non-ports (decided, recorded in the Phase 1 ADR)

  • No inbound use-case ports. The generated AdminApi/StatementsApi/AuditApi interfaces are the inbound contracts and REST is the only driver. Revisit only if a second driver (queue consumer, CLI) appears.
  • Request context is a parameter, not a port. RequestInfo becomes a method argument resolved by controllers via infrastructure.web.RequestInfoProvider. Thread-local reads (RequestContextHolder/SecurityContextHolder) from services are fragile — especially with audit's virtual-thread executor, where the request thread may be gone when the task runs.
  • Audit is a cross-feature public service, not a port. House rule: features talk via public services. AuditService becomes the single entry point; AuditHelper stays as a caller-side convenience inside statement/search/.

6Phased migration plan

Every phase is one PR; the build is green (mvn clean verify) after each; the ArchUnit freeze store shrinks monotonically from Phase 2 onward and must never grow.

Phase 0 — Behavioral pre-flight 3 small PRs

Purpose: eliminate every silent-breakage vector before a single class moves.

  • 0a — Config-prefix fix (F2, D6). Change SignedLinkCleanupProperties prefix to singular statement.signed-link.cleanup. Add a @ConfigurationProperties binding test (Given yml values / When context binds / Then all six properties populate). Review the newly-live values in application*.yml and infra/config-repo/statement-service/*.yml in the same PR — they take effect for the first time.
  • 0b — LoggingAspect re-target (F1, D5). Replace package pointcuts with @within(org.springframework.web.bind.annotation.RestController) and @within(org.springframework.stereotype.Service). Add LoggingAspectTest proving advice fires on an annotated bean — this test is the tripwire for every later move.
  • 0c — URL characterization IT. Integration test pinning the signed-link URL shape (token, ?expires=, &signature=) to protect the Phase 4 DownloadUrlProvider extraction.
Phase 0 execution findings (2026-08-11):
  • Authorization bug found and fixed: SecurityConfig guarded /api/v1/statements/*/link — a route that does not exist. The real endpoint is /api/v1/statements/link/{id}, which fell through to anyRequest().authenticated(), so any authenticated JWT could mint signed links. Matcher corrected to /api/v1/statements/link/*; a wrong-role → 403 test now pins it. The pre-existing SecurityFilterChainIT link test had the same wrong path and passed vacuously (404 satisfies "not 401/403") — path corrected.
  • 0b addendum: SignedLinkCleanupService was @Component, not @Service — a pure annotation retarget would have silently dropped its logging. Changed to @Service for coverage parity.
  • New backlog item — deterministic token collision: the signed-link token is HMAC(method|basePath|expires) with no nonce, so minting links for the same file within the same second stores duplicate tokens, and findByToken then throws IncorrectResultSizeDataAccessException on download. Fix (include link id or nonce in signed data, plus a unique index on token) is a signing-scheme change — scheduled as backlog, not Phase 0.

Phase 1 — ArchUnit ratchet + ADR design

Purpose: make the target architecture executable before restructuring (D4).

  • Add com.tngtech.archunit:archunit-junit5 (test scope) and archunit.properties: freeze.store.default.path=src/test/resources/frozen, freeze.refreeze=false.
  • ArchitectureTest (surefire, *Test) with 7 rules, each wrapped in FreezingArchRule.freeze(...):
    1. No cycles between top-level slices
    2. Features do not depend on ..infrastructure..
    3. ..shared.. depends on neither features nor infrastructure
    4. @RestController classes reside in ..infrastructure..
    5. Generated ..api../..model.api.. accessed only from ..infrastructure.. (D3)
    6. Constructor injection only — no field @Autowired
    7. No java.io.File/javax.crypto outside infrastructure..
  • Commit the initial freeze store capturing the legacy layout. Spot-check the ratchet: add a deliberate violation locally, watch it fail, revert.
  • ADR "Adopt feature-first hexagonal packaging" in the same PR, following docs/standards/adr-guidelines.md numbering rules (create the file to claim the number). Records D1–D7 and the deliberate non-ports.

Phase 2 — Shared infrastructure + shared/ mechanical

Purpose: clear the technical periphery so feature moves are clean.

  • git mv per package cluster: config/* → infrastructure/{config,scheduler,security,crypto}, filter/ + advice/ + CommonUtil + RequestInfoProvider → infrastructure/web/, aspect/ → infrastructure/logging/, RequestInfo + DateMapper → shared/. Then spotless:apply.
  • Create infrastructure/config/ClockConfig (java.time.Clock bean, F7) — the only new class in this phase, so it exists before its first consumer (AuditService, Phase 3).
  • Interim tolerated (stays frozen): services still injecting RequestInfoProvider — burned down in Phases 5–6.
  • Verify: mvn clean verify; freeze store shrinks; LoggingAspectTest green; ApplicationContextSmokeIT green (root package unchanged → scanning intact).

Phase 3 — audit/ feature ~30% design

Purpose: smallest feature first — proves the pattern end to end.

  • Move all audit classes per destination map.
  • Design work: AuditQueryService returns a domain page; AuditController maps to AuditLogPage via AuditApiMapper (rule 5 violation count drops). Executor extracted to AuditAsyncConfig; AuditService takes ExecutorService + Clock via constructor.
  • Verify: mvn clean verify; audit endpoint JSON unchanged (contract is source of truth); store shrinks.

Phase 4 — statement/ core + signedlink/ ~40% design

  • Move statement core (entity, repository, StatementService, DTO, entity mapper, 2 exceptions) and all signedlink classes per destination map.
  • Design work: LinkSigner port + HmacSha256LinkSigner; DownloadUrlProvider port + ServletDownloadUrlProvider (servlet code leaves SignedLinkService); Clock (bean from Phase 2) injected into signedlink + statement services; SignedLinkCleanupScheduler split with @SchedulerLock name and cron key copied verbatim.
  • Verify: mvn clean verify; Phase 0c URL IT green; scheduler smoke unchanged; store shrinks.

Phase 5 — statement/upload/ + storage & crypto ports ~40% design

  • Move upload classes, AdminController, UploadResponseApiMapper per destination map.
  • Design work: StatementFileStore + FileCipher ports; FileStorageService → LocalStatementFileStore; EncryptionService → AesGcmFileCipher; digest → Sha256Digest; upload path uses ports; StatementUploadService accepts RequestInfo from the controller.
  • Verify: mvn clean verify; upload round-trip IT (encrypt → store → exists) green; renamed tests keep their original Given_When_Then cases; store shrinks.

Phase 6 — statement/search/ + statement/download/ ~50% design — heaviest

  • Move search + download classes, StatementsController + StatementApiMapper per destination map.
  • Design work: StatementQueryService returns domain types; StatementsController owns mapping to StatementSummary(Page) — rule 5 violations reach zero; DownloadService uses StatementService lookup + FileCipher + StatementFileStore — no java.io.File, no repository bypass (D7); RequestInfo parameterized on the search path.
  • Delete the now-empty legacy packages: controller/ service/ mapper/ util/ exception/ model/ repository/ aspect/ filter/ config/ security/.
  • Verify: mvn clean verify; download IT matrix (ok / expired / used / invalid-signature / file-missing / decryption-failed) green; JSON contracts unchanged.

Phase 7 — Ratchet close-out mechanical complete

  • Freeze store is empty → delete it; unwrap FreezingArchRule to plain rules (rules were never weakened, only violations removed).
  • Final spotless:apply; README architecture section update; record the test backlog (§8).
  • Verify: mvn clean verify from clean — flushes stale generated MapStruct implementations.
Phase 7 execution findings (2026-08-12):
  • MapStruct field-injection fixed for real, not exempted. The end-of-Phase-6 store held one permanent-looking violation: MapStruct's generated *ApiMapperImpl classes field-inject their DateMapper collaborator (all three mappers using uses = {DateMapper.class}). Rather than freeze this forever, added injectionStrategy = InjectionStrategy.CONSTRUCTOR to all three @Mapper annotations — a standard MapStruct option, zero behavior change. This broke the three mapper unit tests, which used Mappers.getMapper(...) (requires a no-arg constructor); fixed by constructing the generated impl directly (new StatementApiMapperImpl(new DateMapper())), which is more explicit anyway. Rule constructorInjectionOnly now passes with zero violations, unfrozen.
  • Cycle rule refined, not permanently frozen. The other remaining violation — a "cycle" between the infrastructure and statement top-level slices — was the expected hexagonal direction (adapters implementing feature-owned ports, and a feature's own adapters depending on shared infrastructure helpers like RequestInfoProvider), already governed precisely by the (independently zero-violation) featureDomainCodeDoesNotDependOnInfrastructure rule. The generic slice-cycle detector was just too coarse to see that. Refined topLevelSlicesAreFreeOfCycles with two ignoreDependency(...) clauses excluding any edge touching an ..infrastructure.. package (at any nesting level) from cycle detection — the rule still watches for genuine cross-feature cycles (e.g. a hypothetical statement ↔ audit), which is its real purpose.
  • Result: all 7 ArchUnit rules pass unfrozen, on merit. The freeze store (src/test/resources/frozen/) and its properties file are deleted; every rule in ArchitectureTest is a plain ArchRule. Full mvn clean verify from clean: 378 unit tests + 13 integration tests, BUILD SUCCESS.
  • docs/Architecture_Overview.md updated beyond the originally-scoped README section — it's the linked "detailed architecture" doc and had a full "Layered Structure" section naming the old controller/service/repository/model packages verbatim, plus stale references to renamed classes (EncryptionService → AesGcmFileCipher/FileCipher, FileStorageService → LocalStatementFileStore/StatementFileStore) and the old package-literal LoggingAspect pointcut description. Left everything else (flows, security model, crypto/signed-link behavior) untouched since it remained accurate.

8Test strategy

  • Tests move with their subjects to mirrored packages; renamed only alongside subject renames; Given_When_Then naming and structure preserved (and added on any touched test).
  • New tests in scope: ArchitectureTest (Phase 1), LoggingAspectTest + cleanup-properties binding test + signed-link URL characterization IT (Phase 0), ServletDownloadUrlProviderTest (Phase 4).
  • Explicit backlog — out of scope for this migration:
    • SignedLinkCleanupServiceTest (currently untested)
    • Controller @WebMvcTest slices (current controller tests are plain Mockito)
    • DateMapper hardcoded Africa/Johannesburg zone
    • Splitting uploadStatement out of statement core (D7)
    • Signed-link token determinism: add a nonce/link-id to the HMAC input and a unique index on signed_links.token (collision found during Phase 0c — see Phase 0 execution findings)

9Effort profile & verification

Roughly 55% mechanical moves / 45% design refactoring, with the design work concentrated in Phases 4–6. Phases 2, 7, and most of Phase 3 are mechanical.

Per-phase gate: mvn clean verify — unit tests (surefire), integration tests (failsafe + Testcontainers PostgreSQL), and from Phase 1 the ArchUnit ratchet. No environment variables needed: Docker/Testcontainers configuration on this machine is durable (~/.testcontainers.properties + failsafe env var in the pom).
Ratchet invariant: from Phase 2 onward the ArchUnit freeze store only ever shrinks. A phase that grows it is rejected in review. The store is deleted in Phase 7 — its absence is the proof the migration is complete.
